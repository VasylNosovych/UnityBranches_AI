# Export-Figma-Section-to-Notion

## Призначення

Експортувати всі прямі дочірні Frames із вказаної Figma Section у файли і додати ці файли на сторінку Notion як окремі File-блоки в порядку сортування за назвою.

## Обов’язкові вхідні дані

Перед початком отримати або визначити:

- URL Figma-файлу та, бажано, `node-id` Section.
- URL сторінки Notion, куди додавати файли; якщо сторінка відкрита в контексті чату, використати її.
- Формат експорту; використовувати PNG за замовчуванням, якщо формат не вказано.
- Масштаб; використовувати налаштування Figma за замовчуванням, якщо користувач не попросив інше.

Не вигадувати Figma URL, назву Section або сторінку призначення. Якщо є кілька можливих Section чи сторінок, попросити уточнення.

## Передумови та налаштування

Перевірити, що:

- користувач має доступ до Figma-файлу та права на експорт;
- користувач має права редагувати сторінку Notion;
- Figma відкривається у спільному браузері, а Notion редагується через Notion MCP, не через браузер;
- перед першою дією у спільному браузері завантажено core browser skills;
- для входу у Figma використовувати secure browser input для пароля або OTP; ніколи не просити секрети в чаті;
- короткий Figma URL зберігає `node-id`; не передавати повторно URL із подвійно закодованою назвою файлу;
- поточний контент сторінки Notion завантажено перед першою зміною.

## Основний процес

1. Відкрити Figma URL у браузері та дочекатися повного завантаження Canvas і Layers.
2. Переконатися, що відкрито правильну сторінку Figma та Section. У Layers розгорнути відповідну групу й Section.
3. Трактувати “Parent Frames” як прямі дочірні Frame вибраної Section. Не включати саму Section, сусідні Section, вкладені елементи Frame або фрейми з інших груп.
4. Виконувати пакетний режим лише після успішного експорту першого Frame або коли користувач явно просить пропустити пілотний тест.
5. Вибрати Frame через Layers або Canvas. Після кожного вибору перевірити назву Frame і `node-id`, щоб не експортувати сусідній об’єкт.
6. Запустити кнопку `Export <назва>` у правій панелі. За замовчуванням використовувати PNG і масштаб 1x.
7. Для надійного захоплення результату відстежити browser download event. Figma може створити blob URL і скасувати звичайне завантаження після завершення передачі; у такому випадку одразу отримати bytes через `fetch(blob URL)` у контексті сторінки, декодувати їх і зберегти як локальний файл. Не вважати відсутність файлу в Downloads доказом невдалого експорту, доки не перевірено download event і blob.
8. Перевірити локальний файл за MIME/type, розміром і роздільною здатністю. Для PNG очікувати `image/png` і ненульовий розмір.
9. Назвати файл стабільно, беручи назву із відповідного Frame і заміняючи заборонені для файлової системи символи на `.`. Наприклад, якщо Frame у Figma називався `2. Фін.звіт: закупівля батареї 1/2`, то файл у Notion повинен називатися `2. Фін.звіт. закупівля батареї 1.2`.
10. Перед редагуванням Notion завантажити поточну сторінку. Зберегти весь наявний контент, зокрема unknown/external-object блоки.
11. Завантажити локальний файл у session file та використати повернутий `file_uri` без змін. Додати його на сторінку окремим блоком:

```markdown
<file source="FILE_URI" />
```

1. Для кількох Frame додавати один `<file>`-блок на кожен файл у послідовності сортування за назвою; не об’єднувати файли в ZIP, якщо користувач цього не просив.
2. Виконати найменший цільовий `contentUpdates` або `contentPatch`, зазвичай вставивши новий File-блок після наявного контенту. Не перезаписувати всю сторінку без потреби.
3. Повторно завантажити сторінку після зміни та перевірити, що кожен File-блок збережений і має канонічний `file://...` source. Не виправляти канонічне форматування Notion, якщо семантика правильна.

## Безпечний режим за замовчуванням

Якщо користувач просить експортувати багато Frame, спочатку експортувати один приклад, додати його на сторінку та повідомити результат. Продовжувати решту лише після підтвердження користувача або коли він явно дозволив пакетний експорт в одному запиті.

## Очікуваний результат

Повідомити:

- кількість успішно експортованих Frame;
- формат і масштаб;
- сторінку Notion, на яку додано файли;
- чи кожен файл додано окремим File-блоком;
- будь-які Frame, які не вдалося експортувати, із конкретною причиною.

Після успішної зміни додати edit reference. Не стверджувати, що пакет завершено, якщо хоча б один запитаний Frame не перевірено.

## Обробка помилок

- Якщо Figma просить вхід, використати secure browser input; якщо доступу немає, зупинитися й повідомити про це.
- Якщо Section або Frame не знайдено, зупинитися та попросити правильний URL або назву; не експортувати схожий об’єкт мовчки.
- Якщо кнопка Export відсутня, перевірити вибір об’єкта, права та налаштування експорту.
- Якщо browser download скасовано, повторити через capture blob URL, а не нескінченно натискати Export.
- Якщо Notion не приймає файл, зберегти локальний файл, повідомити про проблему завантаження та не створювати порожній або вигаданий File-блок.
- Якщо один Frame у пакетному режимі не вдався, зафіксувати успішні файли, назвати невдалий Frame і зупинити пакет, якщо користувач не попросив продовжити.

## Приклад

Вхід: Figma URL з `node-id=3575-2`, назва Frame `14. Підсумкова таблиця`, сторінка [Допис-звіт](https://app.notion.com/p/3f0e2c94c1dd809199feed902bc6a6c8?pvs=21).

Результат: PNG Frame `14. Підсумкова таблиця`, перевірений як `image/png`, доданий на сторінку одним окремим File-блоком. У фінальному повідомленні зазначити успішний результат і не починати інші Frame без дозволу користувача.
